## Scope

1. **Save selected code directly from VS Code.** Add Snippo: Save Selected Code command and editor context-menu action visible for nonempty selection. Capture only explicitly selected text (no automatic file/workspace scanning or upload); use active editor languageId as suggested language, prompt for name/category/language, allow cancellation at each step, show confirmation before sending if needed to make remote storage clear. Preserve whitespace and exact selection; reject blank/multiple ambiguous selections with clear feedback, or explicitly support them without silently concatenating. Use authenticated existing POST /api/snippets semantics or compatible versioned extension path. Server derives owner, validates payload/size, returns useful duplicate/conflict and service errors; no silent overwrite or unsafe automatic retry. Success only after server confirms; sign-in flow unchanged. New snippet appears in web library and subsequent picker.
2. **Recently used snippets at the top.** On web and extension show a compact Recently Used group (suggest 5 entries) above ordinary results, sorted by last successful copy (web) or insert (extension). Do not count preview/open/search or failed/cancelled actions; no general usage analytics. Private account-scoped timestamps, persist across devices; avoid duplicate cards in the same view if practical without corrupting pagination/count, keep full-library sorting/filtering consistent, respect hidden defaults and deleted targets. Group only matching visible results; no extra blocking request for initial library or insertion. Integrate recent data into existing scoped read or an opt-in compatible API response; record usage after successful action asynchronously/best effort with CSRF/bearer auth respectively, bounded timeouts, no repeated retries, no delaying clipboard/editor insertion, no failure masquerading as copy/insert failure. Limit retained rows per account (e.g. 20 recent personal/shared each or 20 combined); avoid unbounded event logs. Use distinct private personal/default preference tables or equivalently enforced FK design, owner-bound RLS and column grants, valid target ownership, user/target deletion cascade, indexes for owner/time and FK as warranted. Do not store code copies or telemetry outside Supabase. Hidden defaults never displayed or eligible for new use; restored entries may reappear if retained.
3. **Programming language alongside category.** Optional independent language field on add/edit/duplicate/save, compact selector/filter and card metadata in both website and extension where relevant. Use small documented allowlist mapping common VS Code language IDs to existing safe highlighters (Python, JavaScript, TypeScript if supported, HTML, CSS, SQL, JSON, shell, plain text etc.); unsupported IDs fall back to unspecified/plain text without failing save. Existing rows remain unspecified or inferred for display only; do not rewrite historical data or misclassify categories. Prefer explicit language for highlighting, retain current category/code inference for legacy unspecified records; do not alter raw code. Add nullable language columns to personal/shared tables as necessary; shared values managed by administrator only, not editable by users. Duplicate copies language. Search/filter/category/sort/pagination/count stay consistent across complete visible scope. Extend new API via explicit opt-in or versioned endpoint while preserving exact legacy sno/name/cat/code responses and old POST behavior.
4. **Better category management.** Compact website management in existing UI, no standalone complex taxonomy. Show user's personal categories and counts, rename category across that user's personal snippets, and move selected personal snippets (or all in a selected category) to an existing/new category using explicit confirmation for bulk operations. Reuse existing text category column; no new global category table, no destructive category deletion or deleting snippets. Distinguish read-only shared categories, do not alter shared defaults or other users; validate names using existing rules, state merge behavior if target exists and confirm affected count, preserve IDs/code/language/favorites/recents, transactionally scope UPDATE by server-derived owner and selected IDs. No per-row query loop. Ensure filters/search/sort/count reflect new categories. Preserve current duplicate-name and category case semantics unless documented.
5. **Keyboard shortcuts (conditional, low complexity).** Provide practical configurable VS Code keybindings for insert/open picker and save selected code; choose non-conflicting contextual defaults only after checking built-in bindings, use editor/selection when clauses and avoid overriding common shortcuts. If no safe default, expose documented commands assignable in Keyboard Shortcuts instead of hijacking keys. Keep existing command IDs and palette commands. No global OS hooks, no mandatory website shortcuts or changes to existing editor behaviour.
6. **Snippet placeholders (conditional, medium complexity ceiling).** Prefer a simple opt-in template mode on personal snippets, default OFF, with a bounded documented named-placeholder syntax such as {{name}}. Existing and non-template snippets must insert literally, including dollar signs, braces, VS Code-like tokens, backslashes and code indentation. Use native VS Code SnippetString appendText/appendPlaceholder/appendTabstop (or equally safe explicit input approach), assign repeated named placeholders the same tabstop when supported, no arbitrary evaluation, shell commands, transforms, nested expressions, regex or environment-variable expansion. Limit placeholder count/name length; clear validation/help and cancel behavior. Website displays/copies original template text literally, no execution; duplication preserves opt-in. Optional additive boolean column with false default if necessary; older extensions continue literal insertion and existing API remains exact. Shared defaults remain read-only; do not enable existing defaults silently. If native API compatibility, safe escaping, meaningful tests or medium complexity cannot be maintained, skip this feature and explain rather than building a large templating engine. Keyboard shortcuts and placeholders are explicitly conditional; other four features required.
