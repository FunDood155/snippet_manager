## 2. Measure real baseline, safely

Without an authorized authenticated session, measure public path plus isolated authenticated fixtures; provide exact manual steps user can run in their own browser/VS Code (DevTools Network/Performance, no exporting sensitive headers). Never report simulated auth timing as real production auth latency.
- Separate DNS, TCP/TLS, TTFB, transfer, total and browser render/interaction time where observable. Measure public and authenticated paths separately. Where cold start cannot be confirmed from telemetry label first-after-idle/cold candidate, not proven cold. No artificial keep-alive or ping loops.

No config edits or new logging deployments. If stats unavailable, use local profiling and say so. Read-only metadata inspection or existing EXPLAIN of SELECTs only on live DB with tightly scoped timeouts; EXPLAIN ANALYZE and load simulations on isolated fixture DB, not production. Never expose row data in plans/reports.

## 4. Root cause analysis and optimization proposals

Rank bottlenecks by measured impact, confidence, complexity, free-tier resource effects and security/regression risk. Distinguish confirmed from suspected; quantify connection vs SQL vs auth/network vs rendering/JS vs client overhead. Compare viable alternatives and expected gain only as estimate, not achieved result. Include:
- request-scoped DB reuse or bounded pooling compatible with serverless and actual pool mode; transaction-local owner identity reset, rollback on failure, no leaked identity, no unsafe global shared connection. Consolidate library/category/hidden reads if evidence supports it; evaluate HTTP connection reuse.
- auth overhead/row-lock contention and duplicate redirects, without skipping provider validation, revocation, verified-email/hold/cutoff checks, CSRF or RLS. No blanket token cache, unsafe offline auth, stale private snippet cache or weakened session checks.
- actual query plan/index improvements only when justified; assess ILIKE/trigram and payload/pagination options without adding needless indexes for tiny library. Preserve exact search/sort/filters/favorites/hiding semantics and API v1.0.0.
- web async mutations and search with stale response cancellation, correct errors/toasts, no unnecessary full reloads, syntax highlighting/render costs, static asset cache policy while preserving no-store on private pages.
- Vercel/Supabase geography, import/cold-start costs and free-tier constraints; no paid services or setting changes in audit.
- VS Code request coalescing/cancellation, progress feedback, safe live fetch before private display; no persistent private-code caching. Any future in-memory cache requires explicit freshness/revocation/isolation analysis and tests; prefer backend gains first. Identify any necessary extension-side changes and Marketplace impact.
- Provisional targets from planning: warm API <500 ms, warm web <1 s, mutation <500 ms, VS Code retrieval <500 ms, local insertion <100 ms, aim 30–50% warm improvement where baseline permits; refine with evidence and realistic network/free-tier limits. Define measurable acceptance thresholds for next package, not promises.
