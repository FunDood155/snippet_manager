## Objective and approved scope

Implement the four previously approved features plus five selected recommendations in one work package (nine distinct enhancements, not ten; export is excluded). Preserve WP-06 layout/branding and functionality. This is the second UI work package; performance measurements and optimization of both website and VS Code/API requests belong to WP-08.

1. **One-click Copy:** visible accessible icon/action on every visible personal/shared card. Copy exact raw code including indentation, whitespace and long/collapsed content, not highlighted markup or preview. Use Clipboard API on secure origin, handle blocked/unavailable clipboard gracefully, toast only after actual success. No external service.
2. **Edit personal snippets:** edit name/category/code in an on-demand compact form, prepopulate safely, save/cancel; preserve draft on validation/service errors, keep stable sno/owner, allow existing duplicate-name behavior, success/error toast. Shared defaults never editable via app; use duplicate instead. Add owner-scoped POST with CSRF, parameterized UPDATE and strict field validation, existing length/request constraints. Do not expose owner as client-controlled field. Narrowly grant UPDATE(name,cat,code) to snippet_app on personal table and add owner-bound UPDATE RLS policy USING and WITH CHECK, retain existing SELECT policy and all ownership/ID protections. No update grant on shared table or owner_id/sno.
3. **Light and dark themes:** two choices inside existing profile/account dropdown. Default existing dark. Light theme uses white/light neutral cards/background, appropriate dark text, neutral borders/code backgrounds; same layout, spacing, logo and existing blue accents (#007ACC and existing blue variants; do not recolor blue components). Persist choice locally across reload/browser restart, graceful fallback when storage blocked. Apply early using same-origin external script/CSP-safe approach to minimize theme flash. Verify contrast, menus/forms/toasts/code and keyboard controls in both themes. No database theme preference or change to auth page flows.
4. **Favorites:** accessible star toggle for any visible personal/shared default; private per-account persistence across sessions/devices, Favorites tab alongside All/Personal/Defaults. Combine with search/category/sort, accurate count and empty state. Keep hidden defaults hidden even if starred; preserve star preference when hiding and restore visibility/star when unhidden. Favorites filtering is website-only; do not change API schema or extension UI. Use POST/CSRF, idempotent favorite/unfavorite and server-derived owner. Use small private preference tables with RLS SELECT/INSERT/DELETE owner predicates, composite keys, FK cascade for user and actual target deletion; prefer distinct personal/default reference tables (or equivalently enforced FK design) so orphaned refs and cross-owner favorites cannot be inserted. Personal FK/ownership checks must ensure target belongs to same user (e.g. composite unique/FK or equivalent enforced DB policy); shared favorite requires valid shared row. No broad privileges, no duplicate code. Unfavorite/deleting a personal snippet/default or account only removes appropriate preference rows; update account deletion docs as needed.
5. **Syntax highlighting:** lightweight self-hosted, license-compatible implementation for common languages (Python, JS, HTML/CSS, SQL and others where reliably supported). Infer conservatively from category/code or use plain text fallback; categories are user-defined, not language metadata. No forced schema language migration, external CDN, remote code processing, unsafe HTML/eval, or execution of snippets. Escape user code and maintain exact source for copying/editing. If using bundled library, pin version, include license, test malicious HTML/JS payloads and keep it small. Use legible colors in both themes.
6. **Expand/collapse long code:** compact preview for long snippets, clear accessible Expand/Collapse action; short snippets unchanged; preserve indentation and full content/copy, horizontal scroll inside code block; avoid hiding controls or creating overflow on mobile.
7. **Sorting:** compact selector for alphabetical name, newest and oldest added, works with filters. Current tables have separate ID ranges and no creation timestamp; do not misrepresent combined ID sorting as true chronological order. Prefer minimal accurate approach: sort by insertion/serial order within clearly labeled personal/shared groups for legacy records (explain historical timing unavailable); if adding creation timestamps, add nullable historical values and defaults for new rows without inventing old dates, define deterministic ordering/fallback. Preserve existing default ordering unless explicitly changed by user. Document chosen semantics. Do not alter IDs or API contract.
8. **Duplicate snippet:** create independent personal copy of a visible personal/shared snippet, ideally prefill New snippet form with original code/category and editable copy name; save only on explicit confirmation. Preserve source, server-derived owner, validation, CSRF and exact code. No access to another user's or hidden default's data; no global modifications.
9. **Snippet count:** count actual results of current combined scope/search/category (including favorites), exclude hidden defaults, clear empty state. Compact label near library toolbar. No extra count query when rows already available.
